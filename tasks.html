지금 할 일

활성 작업은 랜딩 페이지 로컬 실행 및 웹 게시입니다. 파일 준비(index.html · .nojekyll)는 끝났고, 아래 실행·게시 단계만 남았습니다.

완료랜딩 페이지 파일 작성 — 26개 스킬 카드 URL이 실제 skills/**/SKILL.md 경로와 일치함을 검증
대기로컬 확인 → 커밋 → 푸시 → GitHub Pages 활성화 (사용자 실행 필요)

남은 작업 순서

체크포인트에 기록된 다음 액션 그대로입니다. 위에서부터 순서대로 진행하면 됩니다.

  1. 1

    로컬에서 랜딩 페이지 확인

    저장소 루트에서 정적 서버를 띄우고, 브라우저로 레이아웃·로고·스킬 카드 링크를 확인합니다.

    # 저장소 루트에서
python3 -m http.server 8000
# 브라우저에서 열기 → http://localhost:8000/
  2. 2

    변경 사항 커밋

    저장소 규칙: 세션당 커밋, 메시지는 type(scope): subject 형식.

    git add -A
git commit -m "feat(site): add static landing page for skills catalog"

    이 페이지(tasks.html)도 같은 세션 변경이므로 함께 커밋됩니다.

  3. 3

    main 브랜치에 푸시

    git push origin main
  4. 4

    GitHub Pages 활성화

    저장소 Settings → Pages → Build and deployment에서:

    Source: Deploy from a branch → Branch: main / 폴더: / (root) → Save

    배포가 완료되면 사이트 주소는 https://kimmandoo.github.io/app-skills/ 입니다. (.nojekyll이 이미 있어 Jekyll 빌드 없이 파일이 그대로 서빙됩니다.)

  5. 5

    라이브 URL을 README에 추가 선택

    사이트가 실제로 열리는 것을 확인한 뒤, README.md에 라이브 주소를 적어두면 방문자가 바로 접근할 수 있습니다.

⚠️
왜 직접 실행해야 하나요?
에이전트 환경에는 명령 실행·git·배포 접근 권한이 없어서, 서버 실행부터 Pages 활성화까지는 사용자가 로컬/웹에서 직접 수행해야 합니다. 이 페이지도 python3 -m http.server 8000을 띄운 뒤 http://localhost:8000/tasks.html로 열거나, 파일을 브라우저에 직접 드래그해서 볼 수 있습니다.
